Playbook: rodar o Playground apontando para o seu computador

O site no GitHub Pages é estático e não compila C++. Por isso a página do Playground chama um programa pequeno que roda no seu computador (tools/servidor_local.py), que compila com o g++ (MinGW) instalado aqui. O código que você escreve não vai para nenhum serviço externo.

Como funciona, em uma linha: navegador (GitHub Pages) → http://localhost:8765 (servidor local) → g++ → resultado dos testes de volta na página.

2. Scripts PowerShell: configurar e ligar com um comando

O projeto traz tools\playground.ps1, que confere o ambiente, instala o que faltar, liga e desliga o servidor e atualiza o projeto. Ele não altera nada sem avisar: só a ação instalar mexe no sistema, e pergunta antes de cada item.

Como abrir o terminal na pasta do projeto

  1. Abra a pasta do projeto no Explorador de Arquivos.
  2. Clique na barra de endereço, digite powershell e pressione Enter (abre o PowerShell já dentro da pasta).
    Alternativa: clique com o botão direito num espaço vazio da pasta → Abrir no Terminal.
  3. Confirme que está na pasta certa: dir tools\playground.ps1 deve listar o arquivo.

Comandos

Sempre no formato abaixo. O -ExecutionPolicy Bypass vale só para esta execução; ele não muda a configuração do seu Windows.

powershell -ExecutionPolicy Bypass -File tools\playground.ps1 diagnosticar
AçãoO que fazQuando usar

ligarLiga o servidor numa janela própria e abre o Playground no navegador. Se já estiver ligado, avisa e não cria outro. Use -SemNavegador para não abrir a página.Toda vez que for estudar

Roteiros

Primeira vez

powershell -ExecutionPolicy Bypass -File tools\playground.ps1 diagnosticar
# se acusar falta de Python ou g++:
powershell -ExecutionPolicy Bypass -File tools\playground.ps1 instalar
# feche e reabra o terminal, e confira de novo:
powershell -ExecutionPolicy Bypass -File tools\playground.ps1 diagnosticar
powershell -ExecutionPolicy Bypass -File tools\playground.ps1 ligar

Dia a dia

powershell -ExecutionPolicy Bypass -File tools\playground.ps1 atualizar
powershell -ExecutionPolicy Bypass -File tools\playground.ps1 ligar
# ... estudar no Playground ...
powershell -ExecutionPolicy Bypass -File tools\playground.ps1 parar

Depois de atualizar o projeto com o servidor ligado (para carregar o código novo)

powershell -ExecutionPolicy Bypass -File tools\playground.ps1 parar
powershell -ExecutionPolicy Bypass -File tools\playground.ps1 ligar

O que você deve ver

  • [ OK ] em verde: item conferido.
  • [ !! ] em amarelo: atenção, mas não impede de usar.
  • [ XX ] em vermelho: precisa corrigir (a mensagem diz como).
  • Depois de ligar, uma janela do servidor fica aberta: não feche enquanto estuda. A página deve mostrar a faixa verde "Executor local conectado".

Atalho opcional: um comando curto

Para não digitar a linha inteira, crie uma função no seu perfil do PowerShell (uma vez só). Ajuste o caminho da pasta do projeto:

notepad $PROFILE    # se der erro de arquivo inexistente: New-Item -Force $PROFILE

Cole no arquivo que abrir, salve e abra um terminal novo:

function pg { powershell -ExecutionPolicy Bypass -File "E:\Documents\UFES\MetodoOtimizacao\tools\playground.ps1" @args }

Depois, de qualquer pasta: pg diagnosticar, pg ligar, pg parar, pg atualizar.

Se o Windows disser que o script está bloqueado (acontece quando o projeto veio de um arquivo .zip baixado): rode Unblock-File tools\playground.ps1 e tente de novo. Se a política da sua máquina ainda impedir, use a alternativa manual da seção 3.

3. Alternativa manual: ligar sem o script

  1. Abra a pasta do projeto no Explorador de Arquivos.
  2. Dê dois cliques em tools\iniciar_playground.bat. Uma janela preta abre e fica aberta: é o servidor.
    Alternativa, no terminal, na raiz do projeto: python tools/servidor_local.py
  3. A janela deve mostrar o caminho do g++ e Servidor em http://localhost:8765/.... Se mostrar NÃO ENCONTRADO, vá para o diagnóstico (seção 5).

4. Usar

  1. Abra o Playground no GitHub Pages (ou http://localhost:8765/pages/playground.html, que funciona igual).
  2. No topo deve aparecer a faixa verde "Executor local conectado". Se aparecer amarela, veja o diagnóstico.
  3. Se o navegador perguntar sobre acesso à rede local / a dispositivos neste computador, clique em Permitir.
  4. Escreva a função da etapa, clique em ▶ Executar testes e leia o resultado.
  5. Ao terminar de estudar, volte à janela preta e pressione Ctrl+C (ou feche a janela).

6. Segurança (por que é seguro deixar ligado)

  • Escuta só em 127.0.0.1: outros computadores da rede não alcançam.
  • Só aceita pedidos de https://gabriee7.github.io e do próprio localhost; qualquer outra página aberta no navegador recebe 403.
  • Roda apenas o código que você escreveu no Playground, com limite de tempo (5 s) e de tamanho.
  • Mesmo assim: desligue ao terminar e não cole nele código de origem desconhecida (ele compila e executa de verdade).
