P3 — Heurísticas de refinamento (busca local)

Leia antes o Guia (as 4 peças e as 5 perguntas). Aqui está a aplicação: cada método, o que pensar, o código e as armadilhas. Os exemplos usam o PRCP (maximização) e remetem à página Problemas para TSP e PET (minimização).

VISÃOO que a P3 pede

Três métodos, todos void, todos recebendo a solução por referência (Solucao& s) para refiná-la in-place:

Ponto de atenção: os pesos acima vêm da P3 da turma 2026-1 (PRCP). Na sua turma os valores e o problema podem mudar; a técnica não. O enunciado também exige: arquivos nome_sobrenome.cpp/.h, pasta Prova3 na Área de Trabalho e erro de compilação = 0,0.
BASEO que vem pronto no código da prova

A prova entrega um código-base e você só escreve nas "áreas indicadas". Normalmente já existem:

  • as variáveis globais da instância e a struct Solucao;
  • ler_dados, calcular_fo(Solucao& s), escrever_solucao;
  • gerar_vizinha(Solucao& s) (o movimento aleatório) e uma construtiva (para criar a solução inicial);
  • no main, uma "área para teste" onde você chama seus métodos.
Use os nomes e assinaturas que a prova dá. Nos exemplos deste site as funções novas têm nomes por extenso (busca_local_primeira_melhora); na prova, o .h traz os nomes exatos (algo como heur_bl_pm) — copie-os da declaração, não invente. Se a randômica receber um parâmetro (const int iter), ele é o orçamento de tentativas.
Q1Busca local randômica

Passo 1 — O que pensar

"Sorteio um vizinho. Se for melhor, fico com ele. Se eu falhar iter vezes seguidas, desisto." Não preciso enumerar a vizinhança — só preciso do gerar_vizinha que já existe.

Passo 2 — Pseudocódigo

repita: melhorou = não faça iter vezes: clone = cópia de s gerar_vizinha(clone); calcular_fo(clone) se clone melhor que s: s = clone ; melhorou = sim se não melhorou: pare

Passo 3 — Código (PRCP, maximiza)

void busca_local_randomica(Solucao& s, const int iteracoes)
{
    Solucao vizinha;
    int melhorou = 1;
    calcular_fo(s);                                   // garante fo válida na entrada
    while (melhorou == 1)
    {
        melhorou = 0;
        for (int i = 0; i < iteracoes; i++)
        {
            memcpy(&vizinha, &s, sizeof(Solucao));    // trabalha numa cópia
            gerar_vizinha(vizinha);                   // 1 movimento ao acaso
            calcular_fo(vizinha);
            if (vizinha.fo > s.fo)                    // PRCP maximiza
            {
                memcpy(&s, &vizinha, sizeof(Solucao));
                melhorou = 1;
            }
        }
    }
}
codigo/prcp/busca_local_prcp.cpp

Passo 4 — Por que cada trecho está ali

  • calcular_fo(s) no início: garante que s.fo é confiável mesmo que quem chamou tenha esquecido.
  • memcpy para vizinha: o movimento é aplicado na cópia; se for ruim, descarta-se a cópia e s não foi tocada (é o "desfazer" mais simples).
  • melhorou volta a 0 a cada rodada: o laço externo só termina quando uma rodada inteira de iter tentativas não melhora nada.
  • Aceitar com > estrito (não >=): aceitar empates pode fazer a busca andar em círculos para sempre.
Ponto de decisão: depois de aceitar um vizinho, esta versão continua a rodada de iter tentativas (como no código de aula do professor). A alternativa é reiniciar a contagem a cada aceite. Ambas estão certas; a diferença é só quanto tempo se gasta. Se a prova pedir uma, siga a prova.
Fraqueza que você deve saber explicar: por ser sorteio, a randômica pode terminar com um vizinho melhor ainda existente (nunca foi sorteado). Ela não garante ótimo local; PM e MM garantem.
Q2Busca local de primeira melhora

Passo 1 — O que pensar

"Varro todos os movimentos em ordem. No primeiro que melhora, fico com ele e recomeço a varredura do início." Se uma varredura inteira não achar nada, estou num ótimo local e paro.

Passo 2 — Pseudocódigo

repita: achou = não para cada movimento (em ordem fixa): aplica o movimento; calcula fo se melhorou: achou = sim; saia dos laços (o movimento FICA) senão: DESFAZ o movimento se não achou: pare

Passo 3 — Código (PRCP, maximiza)

void busca_local_primeira_melhora(Solucao& s)
{
    int melhorou = 1;
    calcular_fo(s);
    while (melhorou == 1)
    {
        melhorou = 0;
        for (int ponto = 0; ponto < num_pts && melhorou == 0; ponto++)
        {
            int posicao_original = s.vet_sol[ponto];
            int fo_original = s.fo;
            for (int pos = 0; pos < num_pos && melhorou == 0; pos++)
            {
                if (pos == posicao_original)
                    continue;                         // não é um movimento
                s.vet_sol[ponto] = pos;               // aplica o movimento
                calcular_fo(s);
                if (s.fo > fo_original)
                    melhorou = 1;                     // fica aplicado; sai dos laços
                else
                {
                    s.vet_sol[ponto] = posicao_original; // desfaz
                    s.fo = fo_original;
                }
            }
        }
    }
}
codigo/prcp/busca_local_prcp.cpp

Passo 4 — Por que cada trecho está ali

  • Os dois for enumeram a vizinhança inteira: todo ponto × toda posição. O continue pula o "movimento" que não muda nada.
  • && melhorou == 0 nas condições dos for: é a forma de "sair dos dois laços" sem goto.
  • Se melhorou, não desfaz — o movimento fica aplicado e s.fo já está atualizada pelo calcular_fo.
  • Se não melhorou, desfaz o vetor e a fo. Esquecer s.fo = fo_original é a causa clássica de fo errada ao final.
Sobre o goto INICIO do professor: voltar para um rótulo anterior (como ele faz) é válido em C++. O perigo é um goto que salte para frente por cima de uma declaração com inicialização (int x = ...;): o compilador recusa, e erro de compilação = nota 0. A versão com while (melhorou == 1) faz o mesmo e elimina esse risco, além de ser mais fácil de ler.
Ponto de decisão (6a): a ordem de varredura muda o resultado. Aqui: pontos de 0 a n−1, posições de 0 a m−1. A variante "PM2" do professor embaralha a ordem dos pontos para não favorecer sempre os primeiros. Sem exigência na prova, a ordem fixa é a mais simples.
Q3Busca local de melhor melhora

Passo 1 — O que pensar

"Varro todos os movimentos sem aplicar nenhum, só anotando qual daria a melhor FO. No fim aplico esse único movimento e repito." Cada passo é o mais "inclinado" possível.

Passo 2 — Pseudocódigo

repita: melhor_movimento = nenhum ; melhor_fo = s.fo para cada movimento: aplica; calcula fo se fo melhor que melhor_fo: anota (movimento, fo) DESFAZ (sempre) se melhor_movimento == nenhum: pare aplica melhor_movimento ; s.fo = melhor_fo

Passo 3 — Código (PRCP, maximiza)

void busca_local_melhor_melhora(Solucao& s)
{
    calcular_fo(s);
    while (1)
    {
        int melhor_ponto = -1;
        int melhor_posicao = -1;
        int melhor_fo = s.fo;                         // referência: o melhor visto ATÉ AGORA
        for (int ponto = 0; ponto < num_pts; ponto++)
        {
            int posicao_original = s.vet_sol[ponto];
            int fo_original = s.fo;
            for (int pos = 0; pos < num_pos; pos++)
            {
                if (pos == posicao_original)
                    continue;
                s.vet_sol[ponto] = pos;
                calcular_fo(s);
                if (s.fo > melhor_fo)                 // compara com melhor_fo, não com s.fo
                {
                    melhor_fo = s.fo;
                    melhor_ponto = ponto;
                    melhor_posicao = pos;
                }
                s.vet_sol[ponto] = posicao_original;  // SEMPRE desfaz: só anotamos
                s.fo = fo_original;
            }
        }
        if (melhor_ponto == -1)
            break;                                    // nenhum vizinho melhora: ótimo local
        s.vet_sol[melhor_ponto] = melhor_posicao;     // aplica só o melhor
        s.fo = melhor_fo;
    }
}
codigo/prcp/busca_local_prcp.cpp

Passo 4 — Por que cada trecho está ali

  • melhor_ponto = -1 funciona como "nenhum movimento achado". No fim, -1 significa ótimo local → break.
  • A comparação é com melhor_fo (o melhor visto até agora), não com s.fo. Comparar com s.fo faria o método guardar o último vizinho melhor que a solução atual, e não o melhor de todos.
  • Desfaz sempre, ao contrário da PM: nesta busca nenhum movimento é aplicado durante a varredura.
  • Só depois da varredura completa é que um único movimento é aplicado, e s.fo = melhor_fo evita um calcular_fo extra.
Custo: cada passo paga a vizinhança inteira (n × (m−1) avaliações no PRCP), mesmo que o primeiro vizinho já fosse bom. Por isso a MM costuma ser a mais lenta por iteração.

O que medimos de verdade

Mesma solução inicial para as três, uma execução (srand(42)). Servem para sentir o comportamento, não como ranking:

Lições: (1) nenhuma das três vence sempre; (2) todas melhoram muito uma solução ruim; (3) no TSP, uma construtiva gulosa (623,11) bate qualquer busca local que partiu de uma rota ruim — a qualidade do ponto de partida importa. É exatamente por isso que a P4 combina construtiva + busca local (GRASP).
EXTRAVariantes e como ganhar o bônus
  • RA2 (randômica "melhor da rodada"): em vez de aceitar logo, guarda o melhor dos iter vizinhos sorteados e só aplica no fim da rodada — mistura MM com sorteio.
  • PM2: primeira melhora com a ordem dos pontos embaralhada (evita viés pelos primeiros índices).
  • Avaliação por delta (bônus de eficiência): recalcular a FO inteira por vizinho custa O(n). Quando o movimento só afeta poucos elementos (no PRCP: o ponto movido e os que conflitam com a posição antiga/nova), dá para atualizar só a diferença. Em instâncias grandes isso é a diferença entre segundos e minutos. Só vale depois que a versão simples estiver correta e compilando.
  • Empates: mantenha >/< estrito. >= pode ciclar entre soluções de mesma FO.
TESTEComo saber que está certo (segundo caminho)
  1. Compila? Sem erro de compilação a nota é 0. Compile com g++ -Wall e leia os avisos.
  2. Roda na instância toy primeiro (a pequena). Imprima FO antes e depois.
  3. A FO nunca pode piorar. Se piorou, suspeite do sinal ou do desfazer.
  4. Recalcule a FO do resultado: copie s, chame calcular_fo e compare com s.fo. Se divergirem, você deixou fo velha (é o que o final do main de exemplo faz).
  5. Reaplique a busca no resultado: PM e MM devem retornar a mesma solução (já é um ótimo local).
