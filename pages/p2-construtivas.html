P2 — Heurísticas construtivas e vizinhança

A P2 é a base da P3: o gerar_vizinha que você escreve aqui é o movimento da busca local, e as construtivas fornecem a solução inicial que a busca refina.

VISÃOO que a P2 pede
QMétodoIdeia
1gerar solução vizinhade uma solução pronta, muda uma decisão
2construtiva aleatóriamonta do zero, toda decisão é sorteio
3construtiva gulosamonta do zero, cada decisão é a de menor custo imediato
4construtiva aleatória-gulosaguloso com sorteio entre as "boas o bastante" (LRC)

Regra do enunciado: todos recebem a solução por referência (Solucao& s) e são void. Na turma de referência, a gulosa de melhor FO da turma ganhava +1,0 ponto (desempate pela média de 3 execuções da aleatória-gulosa).

MODELOComo pensar uma construtiva

Uma construtiva começa vazia e toma decisões em sequência. Três perguntas resolvem qualquer uma:

1
O que é uma "decisão"?
PRCP: escolher a posição de um ponto. TSP: escolher a próxima cidade. PET: escolher a tripulação de uma tarefa.
2
Como medir o custo imediato de uma decisão?
Só com o que já foi decidido. PRCP: conflitos com pontos já rotulados. TSP: distância até a próxima cidade. Esta é a "inteligência" do guloso — e a parte que dá o bônus.
3
Em que ordem decido?
Em ordem de índice (mais simples) ou por algum critério (ex.: tarefas por horário de início). A ordem também faz parte da qualidade.
Pegadinha clássica: ao medir o custo parcial, os elementos ainda não decididos têm lixo no vetor. Só considere os já decididos (no PRCP: outro_ponto < pt). Esquecer isso gera uma "gulosa" que decide com base em ruído.
Q1Gerar solução vizinha

Pensamento: sorteio um elemento e mudo sua decisão para outra diferente. Este é o movimento (peça 2 do Guia).

// Q1 — vizinha: parte de uma solução COMPLETA e muda UMA decisão.
void gerar_vizinha(Solucao& s)
{
    int pt = rand() % num_pts;
    int pos;
    do
        pos = rand() % num_pos;
    while (pos == s.vet_sol[pt]);
    s.vet_sol[pt] = pos;
    calcular_fo(s);                                   // sem isso a fo fica velha
}
codigo/prcp/construtivas_prcp.cpp
  • O do ... while (pos == s.vet_sol[pt]) garante que a vizinha seja de fato diferente.
  • calcular_fo(s) no final: deixa a fo atualizada dentro da solução.
O que muda de uma base para outra: na resolução de P2 do professor que vimos (sdTSP), gerar_vizinha e as construtivas não chamam calcular_fo — o main chama depois. Se a sua prova pedir assim, siga; se não disser nada, chamar lá dentro é seguro nos dois casos (só custa um recálculo). O perigo é ninguém calcular.
ProblemaO que o gerar_vizinha faz
PRCPsorteia 1 ponto, nova posição diferente
TSP / sdTSPsorteia 2 posições diferentes e troca as cidades (swap)
PETsorteia 1 tarefa, tira da tripulação e insere em outra
Ponto de atenção: se num_pos == 1 o laço do-while nunca termina (não existe "outra" posição). Em instâncias com m ≥ 2 (como as da prova) não ocorre; vale saber como cai.
Q2Construtiva aleatória

Pensamento: toda decisão é sorteio. Serve de linha de base (e de ponto de partida diverso para a busca local).

// Q2 — construtiva aleatória: toda decisão é sorteio.
void heuristica_construtiva_aleatoria(Solucao& s)
{
    for (int i = 0; i < num_pts; i++)
        s.vet_sol[i] = rand() % num_pos;
    calcular_fo(s);
}
codigo/prcp/construtivas_prcp.cpp
Resultado real (PRCP, 25 pontos): a aleatória deixa só 4 dos 25 pontos livres (a gulosa chega a 17) — por isso ela serve só de linha de base.
Em problemas de permutação (TSP, sdTSP) "aleatória" não é rand() % n por posição — isso repete cidades. Parte-se da permutação 0,1,2,... e embaralha-se (Fisher–Yates): para cada i, troca com um j sorteado em [i, n−1].
Q3Construtiva gulosa

Pensamento: para cada elemento, avalio todas as opções e escolho a de menor custo imediato. "Míope": não vê o futuro.

Passo 1 — A função de custo parcial

// Quantos conflitos a posição 'pos' do ponto 'pt' cria com os pontos JÁ decididos (índice < pt).
// Os pontos de índice >= pt ainda têm lixo em vet_sol — não podem entrar na conta.
int contar_conflitos_parciais(const Solucao& s, int pt, int pos)
{
    int id = get_id(pt, pos);
    int conflitos = 0;
    for (int j = 0; j < vet_qtd_conf[id]; j++)
    {
        int outro_ponto = get_ponto(mat_conflitos[id][j]);
        int outra_posicao = get_posicao(mat_conflitos[id][j]);
        if (outro_ponto < pt && s.vet_sol[outro_ponto] == outra_posicao)
            conflitos++;
    }
    return conflitos;
}

Passo 2 — A gulosa

// Q3 — construtiva gulosa: em cada decisão, escolhe a de menor custo imediato.
void heuristica_construtiva_gulosa(Solucao& s)
{
    for (int i = 0; i < num_pts; i++)
    {
        int melhor_posicao = 0;
        int menor_custo = contar_conflitos_parciais(s, i, 0);
        for (int pos = 1; pos < num_pos; pos++)
        {
            int custo = contar_conflitos_parciais(s, i, pos);
            if (custo < menor_custo)                  // empate: fica com a primeira
            {
                menor_custo = custo;
                melhor_posicao = pos;
            }
        }
        s.vet_sol[i] = melhor_posicao;
    }
    calcular_fo(s);
}
codigo/prcp/construtivas_prcp.cpp
Ponto de decisão (empate): quando duas posições empatam em custo, este código fica com a primeira (< estrito). Outro critério (a última, ou sorteio) muda a solução final. Para o bônus, pense em critérios de desempate e em contar também conflitos "futuros" (posições que bloqueiam muitas opções dos pontos seguintes).
Resultados medidos (PRCP, srand(42)): 25 pts: aleatória 4 → gulosa 17; 500 pts: 263 → 404; 1000 pts: 293 → 575. Uma boa construtiva já vale muito — e depois a busca local ainda melhora (ex.: 1000 pts chega a ~727).
Q4Construtiva aleatória-gulosa (LRC)

Pensamento: a gulosa sempre produz a mesma solução (presa). Em vez de só o 1º colocado, monto uma Lista Restrita de Candidatos (LRC) com os "bons o bastante" e sorteio um deles. Cada execução gera uma solução diferente e boa — a base do GRASP. 

// Q4 — aleatória-gulosa (LRC): sorteia entre as posições "boas o bastante".
// per_ale = 0 => 100% gulosa;  per_ale = 1 => 100% aleatória.
void heuristica_construtiva_aleatoria_gulosa(Solucao& s, float per_ale)
{
    int custo[MAX_POS];
    int lista_restrita[MAX_POS];
    for (int i = 0; i < num_pts; i++)
    {
        int custo_minimo = 1000000000;
        int custo_maximo = -1;
        for (int pos = 0; pos < num_pos; pos++)
        {
            custo[pos] = contar_conflitos_parciais(s, i, pos);
            if (custo[pos] < custo_minimo) custo_minimo = custo[pos];
            if (custo[pos] > custo_maximo) custo_maximo = custo[pos];
        }
        float limite = custo_minimo + per_ale * (custo_maximo - custo_minimo);
        int tamanho = 0;
        for (int pos = 0; pos < num_pos; pos++)
            if (custo[pos] <= limite)                 // quem passa na nota de corte entra na LRC
                lista_restrita[tamanho++] = pos;
        s.vet_sol[i] = lista_restrita[rand() % tamanho];   // tamanho >= 1 sempre (o mínimo passa)
    }
    calcular_fo(s);
}

A outra "aleatória-gulosa": percentual de decisões aleatórias (estilo do professor)

No sdTSP da resolução do professor, per_ale é uma porcentagem: as primeiras per_ale% decisões são sorteadas e o restante é guloso. Mesma ideia (misturar acaso e guloso), mecanismo diferente do corte da LRC acima. Versão equivalente para o PRCP: 

// Variante "percentual" (como o professor fez no sdTSP): as primeiras decisões são SORTEADAS
// e as demais são GULOSAS. per_ale é a PORCENTAGEM (0 a 100) de decisões aleatórias.
int escolher_posicao_gulosa(const Solucao& s, int pt)
{
    int melhor_posicao = 0;
    int menor_custo = contar_conflitos_parciais(s, pt, 0);
    for (int pos = 1; pos < num_pos; pos++)
    {
        int custo = contar_conflitos_parciais(s, pt, pos);
        if (custo < menor_custo)
        {
            menor_custo = custo;
            melhor_posicao = pos;
        }
    }
    return melhor_posicao;
}

void heuristica_construtiva_aleatoria_gulosa_percentual(Solucao& s, float per_ale)
{
    int quantidade_aleatorias = (int) ((per_ale / 100.0f) * num_pts);
    for (int i = 0; i < num_pts; i++)
    {
        if (i < quantidade_aleatorias)
            s.vet_sol[i] = rand() % num_pos;          // fase aleatória
        else
            s.vet_sol[i] = escolher_posicao_gulosa(s, i); // fase gulosa
    }
    calcular_fo(s);
}

Resultado real (PRCP, 25 pontos): LRC: 0,0 → 16 · 0,3 → 15 · 1,0 → 4. Percentual: 0% → 17 · 30% → 16 · 100% → 7. Mesmos extremos, caminhos diferentes — uma execução só, para ilustrar.
Ponto de atenção: leia o enunciado: se ele disser "percentual", é divisão por 100 e int; se falar em "lista restrita", é a LRC. Na dúvida entre os dois, implemente o que o código de aula da turma usa e documente em um comentário.
Por que a LRC nunca fica vazia: o próprio candidato de custo mínimo sempre passa no limite (mín ≤ mín + α·faixa), então tamanho ≥ 1 e o rand() % tamanho é seguro. Se o enunciado der per_ale em porcentagem (0–100), divida por 100.

Gulosa para TSP (vizinho mais próximo), verificada:

// Construtiva gulosa (vizinho mais próximo): a cada parada, vai para a cidade ainda não visitada mais barata.
void heuristica_construtiva_gulosa(Solucao& s)
{
    int visitada[MAX_CIDADES];
    memset(visitada, 0, sizeof(visitada));
    s.vet_rota[0] = 0;                                // começa na cidade 0
    visitada[0] = 1;
    for (int parada = 1; parada < num_cidades; parada++)
    {
        int atual = s.vet_rota[parada - 1];
        int melhor_cidade = -1;
        for (int c = 0; c < num_cidades; c++)
        {
            if (visitada[c] == 1)
                continue;
            if (melhor_cidade == -1 || matriz_custo[atual][c] < matriz_custo[atual][melhor_cidade])
                melhor_cidade = c;
        }
        s.vet_rota[parada] = melhor_cidade;
        visitada[melhor_cidade] = 1;
    }
    calcular_fo(s);
}
