Aulas P3: do zero ao molde que serve para qualquer problema

Quatro aulas curtas, na ordem. Os exemplos usam a P3 de referência (a pasta prova3, problema dos hubs), mas o foco é o molde, que se aplica a qualquer problema. Depois, treine no Exercício P3.

Aviso permanente: o problema da prova pode não ser os hubs. O que se repete é o método; os nomes, o movimento e o sinal mudam. Aula 3 ensina a descobri-los.

Aula 1: a ideia, ligada ao texto da prova

Imagine que você está num prédio, no escuro, e quer chegar ao andar mais baixo. Você só sente os degraus ao redor: apalpa um, se for mais baixo você vai para ele, se não, ignora. Quando nenhum vizinho é mais baixo, você para: é o ótimo local. As três buscas só mudam como você apalpa e quando você anda.

Por que troca e não "mudar um só"? Imagine um time de 3 titulares: para mudar a escalação você tira um e põe um reserva. Pôr um sem tirar ninguém deixaria 4 em campo, e o time seria inválido. Na prova, "exatamente k" significa troca.

Aula 2: o molde genérico das três buscas

Imagine uma receita em que só trocam os ingredientes: o modo de preparo é sempre o mesmo. Em qualquer problema, só três pedaços mudam. Nos códigos abaixo eu os marco com <...>:

MarcadorPergunta que você responde
<PERCORRER>Quais movimentos existem? (os for que geram todos)
<MOVER>Como aplico um movimento na vizinha? (as linhas que mexem no vetor)
<MELHOR>Qual é o sinal? (< se minimiza, > se maximiza)

O molde: 3 linhas que se repetem

memcpy(&vizinha, &s, sizeof(Solucao));   // 1) copia: s fica intacta
<MOVER>                                   // 2) mexe só na cópia
calcular_fo(vizinha);                     // 3) dá a nota à cópia

Imagine um rascunho: você copia a folha original, rabisca no rascunho e só passa a limpo se ficou melhor. A original nunca é rabiscada. Se a vizinha não melhora, não há nada para desfazer.

1) Primeira melhora: aceita a primeira vizinha melhor e recomeça

void heuristica_PrimeiraMelhora(Solucao& s)
{
    INICIO: ;                                    // marca onde recomeçar
    <PERCORRER todos os movimentos>              // for(...) for(...)
    {
        memcpy(&vizinha, &s, sizeof(Solucao));   // copia
        <MOVER na vizinha>                       // move
        calcular_fo(vizinha);                    // nota
        if (vizinha.fo <MELHOR> s.fo)            // melhorou?
        {
            memcpy(&s, &vizinha, sizeof(Solucao));   // sim: s vira a vizinha
            goto INICIO;                             // e recomeça a varredura
        }
    }
}

2) Melhor melhora: olha todas, guarda a melhor, só no fim anda

void heuristica_MelhorMelhora(Solucao& s)
{
    while (1)
    {
        Solucao melhor;
        memcpy(&melhor, &s, sizeof(Solucao));        // melhor começa igual a s
        <PERCORRER todos os movimentos>
        {
            memcpy(&vizinha, &s, sizeof(Solucao));   // copia
            <MOVER na vizinha>                       // move
            calcular_fo(vizinha);                    // nota
            if (vizinha.fo <MELHOR> melhor.fo)       // melhor que a MELHOR vista?
                memcpy(&melhor, &vizinha, sizeof(Solucao));   // guarda
        }
        if (melhor.fo <MELHOR> s.fo)                 // alguma vizinha venceu s?
            memcpy(&s, &melhor, sizeof(Solucao));    // aplica só a melhor
        else
            break;                                   // nenhuma venceu: acabou
    }
}

A diferença da primeira melhora: não anda dentro do laço. Compara com melhor.fo (não com s.fo) e só no fim decide.

3) Randômica: em vez de percorrer, sorteia

void heuristica_randonica(Solucao& s, int INTER)
{
    while (1)
    {
        int achou_melhora = 0;                       // 0 = nada melhorou nesta rodada
        for (int tentativa = 0; tentativa < INTER; tentativa++)
        {
            memcpy(&vizinha, &s, sizeof(Solucao));   // copia
            gerar_vizinha(vizinha);                  // <MOVER> com sorteio
            calcular_fo(vizinha);                    // nota
            if (vizinha.fo <MELHOR> s.fo)
            {
                memcpy(&s, &vizinha, sizeof(Solucao));
                achou_melhora = 1;
            }
        }
        if (!achou_melhora) break;                   // rodada sem melhora: para
    }
}

Aqui o <PERCORRER> vira o for de INTER, e o <MOVER> vira gerar_vizinha (veja a Aula 4).

Laçosfor de INTERtodos os movimentostodos os movimentos

Aula 3: como achar e interpretar os três marcadores em qualquer problema

Esta é a ponte entre o molde e o problema novo. Siga as 4 perguntas, nesta ordem, sempre com o enunciado e o .h abertos.

Pergunta 1: o que é a solução? (leia a struct)

Procure a struct Solucao no .h e o comentário ao lado do vetor. Anote o que cada posição significa e o que cada valor significa.

hubs:      int vet_sol[MAX_NOS];       // [num_hub | num_nos - num_hub]
           posição = lugar na lista; valor = id da cidade
máquinas:  int vet_maquina[MAX_TAREFAS];
           posição = a tarefa;       valor = a máquina onde ela está

Pergunta 2: qual é o movimento? (leia a regra de viabilidade)

Procure frases como "para que uma solução seja viável…". O movimento não pode quebrar essa regra. Sem regra rígida, o movimento é o menor passo possível.

Regra no enunciadoMovimento
"exatamente p hubs" (ou "exatamente k")troca: um sai, um entra
cada tarefa em exatamente 1 máquinamudar a máquina de uma tarefa
a solução é uma permutação (rota, ordem)trocar a posição de dois elementos

Pergunta 3: como percorro? (um for por escolha do movimento)

Conte o que o movimento escolhe. Cada escolha vira um for em <PERCORRER>, e o produto dos tamanhos é o tamanho da vizinhança.

ProblemaO movimento escolhe…<PERCORRER>Vizinhas
Hubsum hub e um não-hubfor pos_hub em 0..num_hub−1; for pos_nohub em num_hub..num_nos−1num_hub × (num_nos − num_hub)
Tarefas em máquinasuma tarefa e uma máquina novafor tarefa; for maquina (pulando a atual)num_tarefas × (num_maquinas − 1)
Rota (permutação)duas posiçõesfor i; for j = i + 1n × (n − 1) / 2

Pergunta 4: qual é o sinal? (procure "minimizar" ou "maximizar")

  • Minimizar: <MELHOR> = <. Foi o caso da P3 de referência (o PDF diz que a FO "deverá ser minimizada").
  • Maximizar: <MELHOR> = >.
  • Empate não é melhora, então use sempre o operador estrito (< ou >), nunca <=.

Preenchendo os três marcadores, lado a lado

Hubs:

// <PERCORRER>
for (int pos_hub = 0; pos_hub < num_hub; pos_hub++)
  for (int pos_nohub = num_hub; pos_nohub < num_nos; pos_nohub++)
// <MOVER>
int aux = vizinha.vet_sol[pos_hub];
vizinha.vet_sol[pos_hub]   = vizinha.vet_sol[pos_nohub];
vizinha.vet_sol[pos_nohub] = aux;
// <MELHOR>  →  <   (minimiza)

Tarefas em máquinas (só para treinar a ponte):

// <PERCORRER>
for (int tarefa = 0; tarefa < num_tarefas; tarefa++)
  for (int maquina = 0; maquina < num_maquinas; maquina++)
    if (maquina != s.vet_maquina[tarefa])       // pula a máquina em que ela já está
// <MOVER>
vizinha.vet_maquina[tarefa] = maquina;
// <MELHOR>  →  <   (minimiza o maior tempo)

Rota (troca de duas cidades):

// <PERCORRER>
for (int i = 0; i < n - 1; i++)
  for (int j = i + 1; j < n; j++)
// <MOVER>
int aux = vizinha.rota[i];
vizinha.rota[i] = vizinha.rota[j];
vizinha.rota[j] = aux;
// <MELHOR>  →  <   (minimiza a distância)
Repare: o esqueleto das três funções (Aula 2) não mudou nenhuma linha. Só estes três pedaços.

Seu roteiro nos primeiros 5 minutos da prova

  1. Abra o .h: copie os nomes da struct, das variáveis e das funções.
  2. Leia a regra de viabilidade: defina o <MOVER>.
  3. Conte o que o movimento escolhe: defina o <PERCORRER>.
  4. Procure "minimizar" ou "maximizar": defina o <MELHOR>.
  5. Encaixe os três no molde da Aula 2.

Aula 4: gerar_vizinha e o rand (onde e como o sorteio acontece)

O professor entrega a gerar_vizinha?

Pelos arquivos da prova3, não. Conferi assim:

  • O prova3.h declara void gerar_vizinha(Solucao& s); (linha 24), mas só declara.
  • No 3.cpp, as funções que o professor entrega (criar_solucao, calcular_fo, escrever_solucao, testar_dados, ler_dados) vêm depois da área "INSIRA SEU CÓDIGO AQUI". A gerar_vizinha não está entre elas.
  • Logo, ela está declarada para você escrever. O enunciado também só pede os métodos das questões 1 a 3, o que reforça que ela é parte do que você faz para a randômica.
Verifique na hora da prova: procure no código-base por gerar_vizinha (Ctrl+F). Se já houver um corpo dela, não a escreva de novo: definir a mesma função duas vezes dá erro de compilação. Se existir só a declaração do .h, escreva a sua. Eu não tenho a prova de amanhã, então confirme.

Onde o rand é chamado?

Só dentro da gerar_vizinha. A randômica não chama rand diretamente: ela chama gerar_vizinha(vizinha), e é essa função que sorteia. O 3.cpp inclui <cstdlib> (linha 5), que traz o rand, então nada a incluir.

O professor usa o rand no criar_solucao (3.cpp, linha 148): int pos = i + rand() % (num_nos - i);. Seguir esse estilo é seguro.

Como funciona rand() % N

Imagine um dado enorme que devolve um número grande e imprevisível. O % N (resto da divisão) o "dobra" para o intervalo 0 a N − 1. Para sortear dentro de um bloco que começa em inicio, some o início: inicio + rand() % tamanho.

Quero sortear…CódigoResultado
um hub (posição)rand() % num_hub0 a num_hub − 1
um não-hub (posição)num_hub + rand() % (num_nos - num_hub)num_hub a num_nos − 1
uma tarefarand() % num_tarefas0 a num_tarefas − 1
Erro clássico: sortear o não-hub com rand() % num_nos. Isso pode cair numa posição de hub, e a "troca" não troca hub por não-hub. Sempre sorteie dentro do bloco certo.

A gerar_vizinha pronta (hubs)

void gerar_vizinha(Solucao& s)
{
    int pos_hub   = rand() % num_hub;                        // sorteia um hub
    int pos_nohub = num_hub + rand() % (num_nos - num_hub);  // sorteia um não-hub
    int aux = s.vet_sol[pos_hub];                            // troca os dois
    s.vet_sol[pos_hub]   = s.vet_sol[pos_nohub];
    s.vet_sol[pos_nohub] = aux;
}

E para tarefas em máquinas, sorteando uma máquina diferente da atual:

void gerar_vizinha(Solucao& s)
{
    int tarefa = rand() % num_tarefas;                // sorteia uma tarefa
    int nova = rand() % num_maquinas;                 // sorteia uma máquina
    while (nova == s.vet_maquina[tarefa])             // tem que ser diferente da atual
        nova = rand() % num_maquinas;
    s.vet_maquina[tarefa] = nova;                     // muda a tarefa de máquina
}

Repare: a gerar_vizinha é o <MOVER> com sorteio. Ela altera s, que na randômica é a vizinha (a cópia).

E o srand?

  • O 3.cpp não chama srand. Então a sequência do rand é a mesma a cada execução: seu resultado é repetível, o que ajuda a depurar.
  • Você não precisa chamar srand para a prova funcionar.
  • Se quiser sorteios diferentes a cada execução, chame srand(time(NULL)); uma vez, no começo da main (o 3.cpp já inclui <time.h>). Não coloque dentro da gerar_vizinha.
  • O arquivo paulo_rizzi3.cpp (que a 3.cpp inclui) não está na pasta; se ele chamar srand, vale o dele.

O que fica de uma rodada para outra na randômica

  • Cada tentativa copia s em vizinha antes de sortear. Se não copiasse, os sorteios se acumulariam na mesma solução.
  • Uma rodada sem nenhuma melhora encerra a busca. Como os sorteios são ao acaso, pode sobrar uma troca que melhora, e a randômica não garante ótimo local.
