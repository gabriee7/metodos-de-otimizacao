P1 — Modelagem do problema

A P1 não tem algoritmo: é traduzir o enunciado em código. Tudo que vem depois (construtivas, busca local, meta-heurísticas) usa exatamente estas quatro peças. Se a calcular_fo estiver errada, tudo que você construir em cima otimiza a coisa errada.

VISÃOO que a P1 pede
QEntregaPeso (TSP, turma de referência)
1método de leitura da instância (recebe o nome do arquivo)0,5
2struct da solução (todas as informações necessárias)0,5
3método de escrita (tela e arquivo) da solução0,5
4método que calcula a FO (com penalização)1,0
Antes de codar, releia o enunciado procurando: o formato exato da instância (a ordem dos números!), o limite de tamanho (ex.: até 200 cidades → #define e vetores estáticos), a penalização (peso e o que penalizar) e o nome da pasta/arquivos. Não presuma — confira.
MODELOComo pensar a modelagem
1
Dados da instância → variáveis globais.
Por quê: são fixos e todos os métodos precisam deles; passar por parâmetro é ruído. O enunciado exige variáveis globais.
2
Solução → struct com o mínimo que a identifica + a fo.
Por quê: você vai ter várias soluções ao mesmo tempo (atual, vizinha, melhor). Por isso a solução é uma struct, e não globais.
3
FO = "quanto custa/vale" uma struct.
Por quê: é a única fonte de verdade para comparar soluções. Restrições que a representação não impede viram penalização na FO (relaxação por penalização).
4
Escrita = para você conferir.
Por quê: é a ferramenta de depuração. Escreva a FO e algo que permita reconstruir a solução real (a rota, as posições).
Penalizar em vez de proibir: uma rota com cidade repetida ou esquecida é uma solução inviável, mas ainda assim representável. Em vez de rejeitá-la, a FO soma peso × violações — assim a busca consegue passar por soluções temporariamente inviáveis e é empurrada de volta para a viabilidade.
Q1Leitura da instância

Exemplo TSP, assumindo "n na 1ª linha e depois a matriz n×n" (confira o formato do seu enunciado):

int num_cidades;
double matriz_custo[MAX_CIDADES][MAX_CIDADES];

typedef struct tSolucao
{
    int vet_rota[MAX_CIDADES]; // rota: vet_rota[i] = cidade visitada na i-ésima parada (0-based)
    double fo;
} Solucao;

void ler_dados(const char* arq)
{
    FILE* f = fopen(arq, "r");
    if (f == NULL)
    {
        printf("Erro ao abrir %s\n", arq);
        exit(1);
    }
    fscanf(f, "%d", &num_cidades);
    for (int i = 0; i < num_cidades; i++)
        for (int j = 0; j < num_cidades; j++)
            fscanf(f, "%lf", &matriz_custo[i][j]);
    fclose(f);
}
codigo/tsp/modelagem_tsp.cpp
  • Recebe o nome do arquivo como parâmetro (exigência do enunciado) e preenche as globais.
  • O formato manda: se o arquivo traz só a parte triangular, ou o depósito separado (sdTSP), a leitura muda — o fscanf precisa seguir a ordem exata do arquivo.
  • Ponto de atenção: se o enunciado indexa de 1 e você usa 0-based, converta na leitura (como nos ids do PRCP: -- após ler).
Q2Struct de solução

Já está no bloco acima (Solucao). Regra prática: o que identifica a solução + a fo.

ProblemaRepresentação
TSPvet_rota[n] (ordem de visita)
PRCPvet_sol[n] (posição de cada ponto)
Mochilavet_sol[objeto] (mochila de cada objeto, −1 = fora)
PETmatriz_sol[tripulação][k] + quantidade[tripulação]
PRVCmatriz_rotas[veículo][k] + tamanho de cada rota
Pegadinha: se a struct tem uma matriz grande, copiá-la por memcpy custa caro — e a busca local copia muito. Dimensione pelos limites do enunciado, não por "um número grande qualquer".
Q3Escrita da solução (tela e arquivo)
void escrever_solucao(const Solucao& s, const char* arq)
{
    FILE* f;
    if (strcmp(arq, "") == 0)
        f = stdout;                                    // "" = escrever na tela
    else
        f = fopen(arq, "w");
    fprintf(f, "FO: %.2f\nRota: ", s.fo);
    for (int i = 0; i < num_cidades; i++)
        fprintf(f, "%d -> ", s.vet_rota[i] + 1);       // mostra 1-based
    fprintf(f, "%d\n", s.vet_rota[0] + 1);             // volta à origem
    if (strcmp(arq, "") != 0)
        fclose(f);
}
codigo/tsp/modelagem_tsp.cpp
  • Uma única função serve para tela e arquivo: "" significa stdout.
  • Recebe a solução por referência (aqui const, pois só lê).
  • Escreve a FO e a rota — "outras informações que permitam compreender a solução real".
  • Só fecha o arquivo se o abriu (nunca fclose(stdout)).
Q4Função objetivo
void calcular_fo(Solucao& s)
{
    int vezes_visitada[MAX_CIDADES];
    memset(vezes_visitada, 0, sizeof(vezes_visitada));
    s.fo = 0;                                          // zerar ANTES de somar
    for (int i = 0; i < num_cidades; i++)
    {
        vezes_visitada[s.vet_rota[i]]++;
        int proxima = s.vet_rota[(i + 1) % num_cidades]; // a última volta para a primeira
        s.fo += matriz_custo[s.vet_rota[i]][proxima];
    }
    for (int c = 0; c < num_cidades; c++)
    {
        if (vezes_visitada[c] == 0)                    // cidade esquecida
            s.fo += PENALIDADE;
        if (vezes_visitada[c] > 1)                     // cidade repetida
            s.fo += PENALIDADE * (vezes_visitada[c] - 1);
    }
}
codigo/tsp/modelagem_tsp.cpp
  • s.fo = 0 antes de somar — senão acumula lixo/valor antigo a cada chamada.
  • (i + 1) % num_cidades faz a última cidade voltar para a primeira (ciclo fechado).
  • Contagem de visitas: 0 vezes = cidade esquecida; > 1 = repetida. Cada falta custa PENALIDADE (100, como no enunciado).
Ponto de decisão: o enunciado deu "pode-se usar o mesmo peso para os dois casos". Se pedir pesos diferentes, separe em duas constantes. Calibração: a penalidade deve ser grande o bastante para que violar nunca compense (maior que o maior custo de aresta).
