Exercício P3: refinamento no UMApHCP (hubs)

Treino no formato da prova: você escreve quatro funções e confere o resultado com números conhecidos. Antes, passe pelos simuladores da página P3 (visão Debug).

Base: use os arquivos da pasta prova3 da disciplina (3.cpp, prova3.h e inst1.txt), com 5 nós e p = 3 hubs. Escreva seu código na área "INSIRA SEU CÓDIGO AQUI". Todas as funções são void e recebem Solucao& s por referência.

  1. Qual é a solução? (O vetor vet_sol.)

Como conferir (resultado determinístico)

Na main, troque criar_solucao(s) por uma solução fixa e calcule a nota:

int v[5] = {0, 1, 2, 3, 4};
for (int k = 0; k < 5; k++) s.vet_sol[k] = v[k];
calcular_fo(s);                                      // espere ≈ 28292,27

As seis vizinhas de [0,1,2,3,4] (3 hubs × 2 não-hubs):

Troca (posição do hub ↔ posição do não-hub)Vetor resultantefo
0 ↔ 33,1,2,0,429701,96
0 ↔ 44,1,2,3,028072,10
1 ↔ 30,3,2,1,427877,07
1 ↔ 40,4,2,3,127877,07
2 ↔ 30,1,3,2,427877,07
2 ↔ 40,1,4,3,227877,07
  • Primeira melhora: termina em 27877,07 com 4,1,0,3,2. Pega a troca 0↔4 (28072,10), recomeça e chega lá.
  • Melhor melhora: termina em 27877,07 com 0,3,2,1,4. Nos empates fica o primeiro encontrado, porque o < é estrito.
  • Randômica: depende dos sorteios (e do srand). Confira só que s.fo nunca piora e que termina abaixo de 28292,27. Com a calcular_fo do professor podem aparecer valores menores que 27877,07 (veja o aviso abaixo).
Atenção: a calcular_fo do professor tem uma peculiaridade. A matriz global mat_custo não é zerada a cada chamada, então a nota de uma mesma solução pode mudar conforme as chamadas anteriores. Conferi compilando o código dele: os números da tabela valem nesta ordem de chamadas (a fo inicial e depois as vizinhas na ordem dos dois for). Por exemplo, os hubs {0, 1, 4} valem de fato 24982,96, mas a função reporta 27877,07 para 4,1,0,3,2 nesse caminho. Se você varrer em outra ordem, a nota final pode diferir.
Na prova: não tente "consertar" a calcular_fo nem confie que a FO final bate com a da tabela do PDF (inst1: 24574,90, hubs {0, 2, 4}). Use as invariantes: a fo nunca piora e a lógica de cada método está certa.

Autocorreção (cinco perguntas)

  • A fo final de cada método ficou ≤ 28292,27?
  • Você usou < e não <=? (Empate não é melhora.)
  • A melhor melhora compara com melhor.fo e não com s.fo?
  • Ao achar uma melhora, a primeira melhora dá goto INICIO? Continuar varrendo está errado.
  • s só mudou depois de você decidir aceitar a vizinha?
Gabarito (abra só depois de tentar)

{

    s.vet_sol[pos_nohub] = no_que_sai;

void heuristica_randonica(Solucao& s, int INTER)
{
    while (1)
    {
        int achou_melhora = 0;
        for (int tentativa = 0; tentativa < INTER; tentativa++)
        {
            memcpy(&vizinha, &s, sizeof(Solucao));
            gerar_vizinha(vizinha);
            calcular_fo(vizinha);
            if (vizinha.fo < s.fo)                  // minimiza: menor é melhor
            {
                memcpy(&s, &vizinha, sizeof(Solucao));
                achou_melhora = 1;
            }
        }
        if (!achou_melhora) break;
    }
}

{
    INICIO: ;
    for (int pos_hub = 0; pos_hub < num_hub; pos_hub++)
        for (int pos_nohub = num_hub; pos_nohub < num_nos; pos_nohub++)
        {

Respostas das 5 perguntas: solução = vet_sol (os num_hub primeiros são hubs); movimento = trocar um hub por um não-hub (o enunciado exige exatamente p hubs); vizinhas = num_hub × (num_nos − num_hub) = 6 na inst1; sinal = <, pois minimiza; descarte = jogar fora a cópia, porque s nunca foi mexida.
